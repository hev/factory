hev factory runs coding agents in the background on a Mac you own. You stay in
the Claude session you already have open. When work is long, parallel, or
should keep going after you walk away, that session hands it to the factory.
Each part runs as its own session and ends in a pull request.

There's no plan file to write and nothing to approve in a tracker. You ask
Claude, and review the pull requests that come back.

<Edition only="oss">

These are the open source docs: the whole factory on one Mac, acting as
whoever is logged in there. Switch to **Pro** at the top of the sidebar for
the laptop-and-server setup.

</Edition>

<Edition only="pro">

These are the pro docs: your laptop as the client, and an always-on Mac as the
server, working under a bot account of its own. Switch to **OSS** at the top of
the sidebar for the one-Mac setup.

</Edition>

## Agent roles

Three kinds of process do the work. Each is a model session with the
factory's CLI, not a program with rules of its own.

## How it runs

<Edition only="oss">

Reception, the jobs, their gaffers and the sessions all run on one Mac. A
`factory tick` every minute, with no model, wakes a gaffer only when something
in its job changed. Every session acts as whoever is logged in on the Mac.

</Edition>

<Edition only="pro">

Reception runs on your laptop, as you. The jobs, their gaffers and the
sessions run on an always-on Mac, as the bot account. A `factory tick` every
minute, with no model, wakes a gaffer only when something in its job changed.
Closing the laptop stops nothing.

</Edition>

## What's real

<Callout label="status">
The docs run ahead of the code on purpose: the site is the spec, and the code is
built against it. **Sessions, jobs and the tick run today** on hev/factory's
`main`. The gaffer is being built now. Packaged loops and the console aren't
built yet<Edition only="pro">, and neither are lines</Edition>. Each page opens
by saying which parts are real.
</Callout>
