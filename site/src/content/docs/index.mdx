Always working.

hev factory puts a coding agent with its own GitHub account on a Mac that never
sleeps. You stay in the Claude session you already have open on your laptop.
When work is long, parallel, or should outlive the lid, that session hands it to
the factory. Each part becomes its own session, runs as **hevbot**, and ends in
a pull request you review like a colleague's.

There is no plan file to write and nothing to approve in a tracker. You just
talk to Claude.

## Two people

**hevbot** does the work. It's an account of its own on the always-on host,
with its own `gh` login, git author, model subscriptions and vault. **You**
ask for the work and review what comes back. The model on your laptop sits
between the two and does the coordinating that the old factory needed a
foreman for.

## What's real

<Callout label="status">
The docs run ahead of the code on purpose: the site is the spec, and the code is
built against it. **Sessions and hosts run today** from the `bitter-lesson`
branch of hev/factory. Lines, packaged loops, goals and the dashboard are
unbuilt, and each page opens by saying which parts are real.
</Callout>

## What happened to the rest

Earlier versions had a front desk, a foreman, a gaffer per plan, an event
controller and a Linear approval door, with about 3,500 lines of contracts
telling models how to coordinate with each other. Given good tools, a model
coordinates better than any charter we wrote. We kept the machine, the
identity, the tracing and the board, and cut everything else.
