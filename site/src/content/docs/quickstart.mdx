<Edition only="oss">

Everything runs on the Mac you're at. Use a Mac that stays awake if you want
work to keep going while you're away.

### 1. Build the CLI

```bash
git clone https://github.com/hev/factory ~/workspace/factory
cd ~/workspace/factory && go build -o ~/.local/bin/factory ./cmd/factory
```

### 2. Check the Mac

Sessions act as whoever is logged in here, so this is whose name goes on the
commits. It needs:

- `claude` (and `codex`, if you use it), logged in
- `gh auth login`, and git's author set
- `tmux`
- hev kit's capture daemon, `hev d`, if you want `factory find` to search
  every session's trace

<Callout label="warning">
Sessions run with permissions off. They run shell commands, commit, push and
open pull requests as this login without asking. Give the Mac only the access
you'd give the work.
</Callout>

### 3. Install the skill

```bash
factory skill install
```

That installs [reception](/docs/reception): the skill that tells Claude when
to hand work to the factory, and how.

### 4. Put the tick on a timer

```bash
factory tick
```

The tick runs every minute, calls no model, and wakes a job's
[gaffer](/docs/gaffer) only when something changed. Run it from launchd, cron
or `loop d`.

</Edition>

<Edition only="pro">

Pro is two machines: your laptop, and an always-on Mac that works as a bot
account of its own. We provision the always-on Mac. These steps are what
provisioning does, if you're doing it yourself.

### 1. Build the CLI on both

The laptop runs `factory _host` on the server over ssh, so both need the same
build:

```bash
git clone https://github.com/hev/factory ~/workspace/factory
cd ~/workspace/factory && go build -o ~/.local/bin/factory ./cmd/factory
```

### 2. Sign the server in as the bot

Sign the always-on Mac in as the [bot account](/docs/identity), not as you. It
needs:

- `claude` (and `codex`, if you use it), logged in on the bot's subscriptions
- `gh auth login` as the bot, and git's author set to the bot
- `tmux`
- hev kit's capture daemon, `hev d`, pointed at the same Layer namespace as
  your laptop's

Nothing of yours goes on this machine.

### 3. Add it as the owner

On the laptop:

```bash
factory hosts add mini        # an ssh alias
factory hosts                 # each host's identity, load, memory and plan headroom
```

Then mark it `owner` in `~/.factory/hosts` (`mini owner`). Every job lives on
the owner, and its tick runs there every minute from launchd.

### 4. Install the skill on the laptop

```bash
factory skill install
```

That installs [reception](/docs/reception) in your laptop's Claude.

</Edition>

### Ask for work

Open Claude and ask for something long, parallel, or overnight:

```text
move searchAfter into both layer repos, the admin after the API
```

Reception files it as a job and tells you what's already moving. `factory
jobs` shows every job, `factory ls` shows every session, and `factory attach
ID` puts you in one.
